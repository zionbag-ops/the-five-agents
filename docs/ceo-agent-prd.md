# PRD — סוכן CEO (מנכ"ל)

## סקירה כללית

סוכן ה-CEO הוא שכבת ה-orchestration הראשית במערכת "The Five Agents". כל בקשה שמגיעה מהמשתמש דרך Claude Code עוברת דרכו — הוא מנתח את המשימה, מחליט אילו סוכני-משנה לפעיל, מתאם ביניהם ומחזיר תשובה מאוחדת.

---

## מטרה ונימוק

מערכת multi-agent לפיתוח תוכנה מורכבת מסוכנים מתמחים — כל אחד מצטיין בתחום ספציפי. ללא orchestrator מרכזי, כל סוכן פועל באופן עצמאי ואין תיאום בין משימות מורכבות. סוכן ה-CEO פותר זאת על ידי:

- נקודת כניסה יחידה לכל משימה
- הפרדה בין ה"מה" (מה המשתמש רוצה) ל"מי" (מי מבצע)
- יכולת לשרשר מספר סוכנים בפרויקטים מורכבים

---

## תחום אחריות

**בתחום:** ניתוח משימות, ניתוב לסוכנים, סינתזת תוצאות, דיווח למשתמש.

**מחוץ לתחום:** ביצוע ישיר של קוד, כתיבת קוד, הרצת בדיקות — אלה תפקידי סוכני-המשנה.

---

## ארכיטקטורה כללית

```
משתמש
   │
   ▼
CLAUDE.md  ──────────────────────►  CEO Agent (.claude/agents/ceo.md)
                                          │
                    ┌─────────────────────┼─────────────────────┐
                    │                     │                     │
                    ▼                     ▼                     ▼
              Agent 1 (TBD)        Agent 2 (TBD)        Agent 3 (TBD)
                                                               │
                                                         Agent 4 (TBD)
```

ה-CEO יכול להפעיל סוכנים בסדרה (כשהתוצאה של סוכן אחד היא הכניסה לבא) או באופן עצמאי לפי הצורך.

---

## דרישות פונקציונליות

### 1. קבלת משימה

- **FR-01:** CEO מקבל כל בקשה שמגיעה מהמשתמש דרך Claude Code.
- **FR-02:** ה-input כולל: תיאור המשימה, הקשר הפרויקט (שפה, ספריות, קבצים רלוונטיים), והיסטוריית שיחה אם קיימת.
- **FR-03:** CEO קורא את ה-CLAUDE.md של הפרויקט בתחילת כל משימה כדי לרענן הקשר.

### 2. ניתוח וסיווג המשימה

- **FR-04:** CEO מזהה את טיפוס המשימה: פיצ'ר חדש, תיקון באג, refactor, בדיקות, code review, שאלת ארכיטקטורה, או שילוב.
- **FR-05:** CEO מפרק משימות מורכבות לתת-משימות וקובע סדר ביצוע.
- **FR-06:** אם המשימה לא ברורה, CEO שואל שאלת הבהרה לפני הניתוב.

### 3. קבלת החלטה — ניתוב לסוכן

- **FR-07:** CEO בוחר סוכן אחד או רשימה מסודרת של סוכנים לפי מטריצת ההחלטות (ראה להלן).
- **FR-08:** CEO מנמק את ההחלטה לפני הביצוע ("אני מפעיל את סוכן X כי...").
- **FR-09:** CEO יכול לנתב למספר סוכנים ברצף (sequential pipeline).

### 4. הפעלת סוכן/ים

- **FR-10:** CEO מפעיל סוכן-משנה ומעביר לו: תיאור המשימה, הקשר רלוונטי, ותצפיות קודמות (אם זו שלב שני ואילך).
- **FR-11:** CEO מגדיר ציפיות ברורות לסוכן: מה הוא צריך להחזיר ובאיזה פורמט.

### 5. מעקב ובקרה

- **FR-12:** CEO מעריך את תוצאת כל סוכן לפני שמחליט להמשיך לסוכן הבא.
- **FR-13:** אם תוצאה לא מספקת, CEO יכול לחזור על אותו סוכן עם הוראות מתוקנות (retry עם הקשר).
- **FR-14:** CEO שומר track של אילו שלבים הושלמו ומה נותר.

### 6. סינתזת תוצאות ודיווח

- **FR-15:** CEO מאחד את תוצאות כל הסוכנים לתשובה מלוכדת אחת.
- **FR-16:** CEO מדווח למשתמש: מה בוצע, על ידי מי (אילו סוכנים), ומה התוצאה.
- **FR-17:** אם יש פעולות שנותרו (למשל, קבצים לבדוק), CEO מציין אותן בבירור.

|------|--------|------------|-----|
| Agent 1 | TBD | `.claude/agents/agent1.md` | לא הוגדר |
| Agent 2 | TBD | `.claude/agents/agent2.md` | לא הוגדר |
| Agent 3 | TBD | `.claude/agents/agent3.md` | לא הוגדר |
| Agent 4 | TBD | `.claude/agents/agent4.md` | לא הוגדר |

**פרוטוקול העברת הקשר (Context Passing Protocol):**

```
Input לסוכן-משנה:
{
  task: string,           // תיאור המשימה הספציפית
  context: {
    project: string,      // שם הפרויקט
    files: string[],      // קבצים רלוונטיים
    previousResults: any  // תוצאות שלבים קודמים (אם קיים)
  },
  expectedOutput: string  // מה CEO מצפה לקבל בחזרה
}
```

## ניהול הקשר ומצב

- **ST-01:** CEO שומר הקשר לאורך כל ה-pipeline של משימה אחת.
- **ST-02:** תוצאת כל סוכן מועברת כ-context לסוכן הבא בשרשרת.
- **ST-03:** CEO לא שומר מצב בין משימות שונות — כל משימה מתחילה מחדש.
- **ST-04:** הזיכרון ארוך-הטווח של הפרויקט שמור ב-`vault/Meeting Notes/` (obsidian-vault-workflow).

---

## טיפול בשגיאות

- **ERR-01:** אם סוכן-משנה נכשל — CEO מדווח למשתמש ומציע חלופה (retry / סוכן אחר / ביצוע ידני).
- **ERR-02:** אם המשימה חורגת מיכולות הסוכנים הקיימים — CEO מודיע ומסביר את הפער.
- **ERR-03:** CEO לעולם לא "ממציא" תוצאות — אם אין תשובה, אומר זאת ישירות.

---

## אינטגרציה עם CLAUDE.md

CLAUDE.md כולל הוראה מפורשת לנתב כל משימה דרך CEO:

```markdown
## Mandatory Agent Routing

For every task in this project, delegate to the CEO agent at
`.claude/agents/ceo.md`. The CEO will analyze the task and
route it to the appropriate sub-agent(s).

Do not bypass the CEO and call sub-agents directly.
```
